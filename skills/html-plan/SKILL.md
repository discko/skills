# HTML Plan

为用户生成可审阅的计划；在浏览器中收集选择、评论、划除和内容编辑。用户显式保存后，反馈写回 HTML 的 head；无法保存时可复制反馈 JSON 并粘贴回聊天。用户在聊天指示下一步时结合反馈处理。

本 Skill 所需脚本和资源全部位于本目录。命令中的 `<skill>` 指本 SKILL.md 所在目录，使用实际绝对路径。需要 Python 3.9+，只依赖标准库。

## 环境初始化

用户要求初始化时，先检查操作系统、可用 Python 和 Chrome。若无 Python，说明缺项并按用户授权协助安装；不要调用尚不存在的解释器。

用已找到的 Python 运行：

```text
python <skill>/scripts/setup.py install
python <skill>/scripts/setup.py doctor
```

安装器会将 host 和扩展复制到稳定的用户目录，生成系统入口并注册。可以反复运行以修复路径或更新。用户无需逐项目安装。不要将临时 Skill 缓存目录直接作为 Chrome 的加载目录。

把安装器返回的 `extensionDirectory` 给用户，指导其在 Chrome 扩展管理页开启开发者模式，加载该目录，并允许访问文件网址。固定扩展 ID 已包含在资源中，无需用户复制 ID。

指导用户打开返回的 `testPage`，通过页面保存一次反馈并重新打开核对。只有用户要求浏览器操作或验证时，才考虑代为操作。`doctor` 仅验证注册、入口和协议，不能据此声称浏览器链路已通过。若浏览器安装步骤尚未完成，准确指出剩余步骤。

首次生成计划时可以检查已有配置；环境尚未就绪也可以生成离线可用的 HTML，并告知可复制反馈 JSON 回聊天或下载含反馈的副本。

## 按任务选择内容与布局

在同一个 Skill 内按用户目的选择，不要求用户先选模式；同一页可以混合两类内容。

- **计划审阅**：围绕要实现的行为、取舍、影响和验证方式组织。把真正会改变实施方式的待定问题做成交互项，其余用说明或证据展示。少量平级内容用 `layout: "flat"`；实现细节较多时用 `cards` 折叠，或仅让局部 claim 使用折叠。层级表达关系，不必凑三层。
- **信息收集与核对**：先从已有代码、数据和上下文预填，并注明来源与不确定之处。重复对象、映射关系、字段清单优先用 `table`，一行一个对象，列对应同类属性；重点让用户补充未知项、纠正推测和解决冲突。少量不同类型问题适合平铺表单。不要为每个属性套三层卡片，也不要在正反两张可编辑表中重复维护同一关系。

区分“已知事实”“建议默认值”和“待确认”。默认值和已查看都不等于用户认可。信息收集中的“不知道”“不适用”“忽略此项”若含义不同，应设计明确选项；不要依赖用户在备注反复写同一句话。不要将未勾选的布尔项解释为“尚未回答”：需要三态时用 radio 或 select。

### 组件选择

- 少量且文字简短的互斥选项：`radio`；默认不选，可用 `default` 提出建议并用 `hint` 说明依据。
- 明确的是/否或启用开关：`checkbox`；可同时选多个值：`checkboxes`。
- 候选很多或值较长：`select`；明确提供“待确认”等选项并设为默认，避免无意把第一项当成决定。
- 短文本、数值、长说明分别用 `text`、`number`、`textarea`。已知的只读事实直接作为文本单元格或说明。
- 表格自带搜索和“有修改或评论／未查看”筛选。每行带备注；容器无须重复收集意见时设置 `feedback: false`。大量信息先用列分组与简短摘要压缩，不要把全部代码和背景放进每一行。

使用 [格式说明](references/format.md) 中的原生字段生成布局，不靠生成后批量替换 HTML 标签。混合示例见 `assets/mixed-review.json`。

## 生成计划

1. 按上述用途选择布局，结合用户需求与可取得的事实组织内容。开发计划需要时按行为 → 实现机制 → 改动位置与验证展开；信息核对按对象与属性组织。
2. **默认将 HTML Plan 放在项目根目录的 `.plan/` 文件夹。用户指定其他目录或文件名时，优先遵从用户要求。** 该目录只是默认生成位置，不是访问限制。
3. 阅读 [计划格式](references/format.md)，生成 JSON 输入。`decision` 表示需要用户选择、补充或纠正的字段，不只代表开发决策。给语义稳定的条目分配稳定 ID；用说明和 exhibits 展示调用流程、数据结构、真实代码片段或静态原型。
4. 调用打包脚本，产出一个独立 HTML；不引用外部 JS、CSS 或 CDN：

```text
python <skill>/scripts/plan.py build <spec.json> <项目>/.plan/<主题>-v1.html --root <项目>
```

需要真实代码时通过 `source` 指定文件及行号，由脚本从项目抽取。敏感信息和无关文件不应出现在计划中。明确区分现有代码与拟议代码。

给出生成文件的绝对路径链接。需要保存反馈时用本机 Chrome 打开 `file://` 页面；内置预览是否能运行 Chrome 扩展不能假定。

交付前默认只做轻量静态检查：JSON／脚本语法、必需字段、ID 唯一性、选项与默认值类型，以及格式规则；同时核对内容依据。复用模板生成计划时，不重复测试模板交互，不默认启动或安装浏览器、运行 Playwright、截图或做视觉检查。只有用户明确要求浏览器操作、页面验证或视觉检查时，才考虑启用相应工具；生成 HTML 本身不构成这类要求。简短说明本页需用户关注的未知或冲突，不要求用户重新填写已知信息。

页面主题默认跟随系统，用户可在页头切换浅色／深色或恢复跟随系统。主题选择只对当前页面生效，不写入反馈、文件或浏览器存储，重新打开默认跟随系统。

内置浏览器或未配置扩展的环境可使用“复制反馈 JSON”。按钮始终显示，连接或保存失败时突出提示。复制成功或失败仅显示 toast，不提供手动复制文本框；复制失败时可重试或下载 HTML 副本。

## 读取反馈与修订

用户说“继续”或要求根据反馈调整时，定位当前讨论的那份 HTML；不要跨主题盲取全项目最新文件。通过脚本读取已保存的 JSON，无需执行页面脚本：

```text
python <skill>/scripts/plan.py review <当前.html>
```

反馈是本轮用户意见，结合当前聊天理解。页面没有 Approve 状态；保存反馈本身不触发代码执行。用户在聊天要求实施时推进实施，要求修订时生成新版，不额外增加页面审批流程。

读取后先归纳本轮修改、备注、明确排除项和未解决冲突，结合生成时的默认值判断哪些是用户修改；不要把每个未修改的默认值宣称为用户确认。信息核对结果用于后续任务的依据，是否实施仍按用户聊天指令判断。

修订计划生成**新文件**，保留旧文件：

```text
python <skill>/scripts/plan.py build <新spec.json> <项目>/.plan/<主题>-v2.html --previous <v1.html> --root <项目>
```

打包器根据稳定 ID 预填评论、类型兼容的选项、划除和编辑，完整保留上一轮反馈。多选值包含失效选项时不迁移该字段，应核对历史后在新版设置合理默认值。模型负责检查对应关系：条目含义改变就使用新 ID；不要将旧意见挂到无关内容。已应用的编辑若不该继续覆盖新内容，应给对应 exhibit 新 ID 并说明变更。新版的“已查看”记录重新开始。

如需精确调整预填内容，在生成的新 HTML 尚未交给用户前调整其 state JSON，并校验格式；不要修改已经交付审阅的旧 HTML。为新版本记录本轮已采纳或待解决的意见。

### 聊天中粘贴的反馈

识别 `type: "html-plan-review"` 的 JSON，按 planId、documentId、documentRevision 核对当前主题的 HTML，按 baseReviewRevision 核对反馈版本。标题只是定位提示；找不到对应文档时请求必要上下文。结合用户聊天中的要求决定修订或实施；单独粘贴 JSON 不代表批准实施。

需要修订时，将粘贴的 JSON 原样保存为临时文件，按以下方式生成新版并预填反馈（不改写旧 HTML）：

```text
python <skill>/scripts/plan.py build <新spec.json> <项目>/.plan/<主题>-v2.html --previous <v1.html> --feedback <粘贴的反馈.json> --root <项目>
```

脚本拒绝文档或反馈版本不匹配的导入。遇到旧版本反馈，先比较差异，结合用户意见映射到新计划；不要篡改版本号强行导入。复制不会更新源文件或递增反馈版本，新版历史记录会标明反馈来自剪贴板。格式见 [计划格式](references/format.md)。

## 保存与故障

仅在页面显式点击“保存反馈”时调用 host。host 校验文档标识和反馈版本，在锁内更新状态区块；保留其他文件字节。

版本冲突拒绝覆盖。页面显示原因并保留输入，用户可复制 JSON 回聊天或下载副本。复制不清除未保存标记，不伪报保存成功。不要通过修改版本号或删除反馈绕过冲突。不要引入目录白名单、常驻服务、自动批准或后台轮询。

0.2.0 的 checkbox／checkboxes 使用布尔值／字符串数组，需要同版本或更高的 host。页面发现旧 host 时提示重新运行 `setup.py install`，期间可复制反馈。旧 HTML 不会自动获得新布局，使用新版生成器生成新文件。

详细初始化与诊断行为见 [安装说明](references/setup.md)。
